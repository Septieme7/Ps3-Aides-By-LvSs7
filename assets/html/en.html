Chapter 4

🕹️ Step 3: Special Cases for PS2 and PS1 Games

To make your PS2 and PS1 games work, simply copying the game files is not enough. Two situations must be distinguished: one where you use CFW Evilnat (as is your case) and one where you use PS3HEN.

🎮 PS2 Games (via CFW Evilnat)

With a CFW, the method is more flexible than with HEN. You don't need to encrypt your ISOs to .BIN.ENC.

  • Required format: You can use your .ISO files directly (unencrypted).
  • Location: Place your .ISO files in the /dev_hdd0/PS2ISO/ folder on the internal hard drive. ISOs stored on an external USB device (FAT32) will be automatically copied to the PS3's hard drive at launch.
  • Configuration file (.CONFIG): Although often optional, a .CONFIG file may be needed for certain specific games to improve compatibility or fix graphical bugs. webMAN MOD has an "Auto CONFIG" option that can automatically copy the configuration file found in the PS2ISO folder if the ISO doesn't have one.

📝 PS2 Configuration File (.CONFIG): Clear Explanation

Some PS2 games need a special configuration file to work better on PS3. This file is separate from the ISO and has a very precise name.

Concrete example:

Example --> /dev_hdd0/PS2ISO/Grand Theft Auto - San Andreas v2.01.iso
        --> /dev_hdd0/PS2ISO/Grand Theft Auto - San Andreas v2.01.iso.CONFIG
  • The first file is the game ISO.
  • The second is the associated configuration file.

The ISO is not being renamed. The ISO keeps its normal name. The .CONFIG file is a small text file created next to the ISO, in the same folder (/dev_hdd0/PS2ISO/).

Naming rule: the .CONFIG file must be named exactly like the ISO, including the .iso extension, then you add .CONFIG at the end.

  • MyGame.iso → MyGame.iso.CONFIG
  • Gran Turismo 4.iso → Gran Turismo 4.iso.CONFIG

What is it for? It allows webMAN MOD / the PS2 emulator to apply specific settings for this game:

  • emulator choice (ps2_emu, ps2_netemu, ps2_gxemu…)
  • compatibility fixes
  • memory management
  • fixing graphical bugs or slowdowns
  • region forcing, etc.

What to do?

  • Keep the ISO and the .CONFIG side by side in /dev_hdd0/PS2ISO/.
  • Do not rename the ISO, otherwise the .CONFIG will no longer be associated and the game will lose its settings.
  • If the game works fine, don't touch anything.
  • If you delete the .CONFIG, the game may still start, but it will lose its specific settings and may show bugs.
💡 Tip: webMAN MOD has an Auto CONFIG option that can automatically copy a .CONFIG found in PS2ISO if the ISO doesn't have one. Here, the file is already present: this is normal and recommended.

🕹️ PS1 Games (via CFW)

For PS1 games, the process is fairly straightforward.

  • Supported formats: .ISO, .BIN/.CUE, and .IMG/.CCD formats are supported. The .cue (or .ccd) file must be next to the .bin (or .img) and have the same name.
  • Location: Place your game files in the /dev_hdd0/PSXISO/ folder.
  • Emulator:
    • By default, webMAN MOD uses the ps1_emu.self emulator. You can switch to ps1_netemu.self via an option in /setup.ps3 for better compatibility with certain games.
  • External PS1 BIOS (optional):
    • The PS3's internal BIOS is used by default.
    • To use an external PS1 BIOS, place a file named ps1_bios.bin in the /dev_hdd0/tmp/wm_res/ folder. This file must be renamed from an official PS1 BIOS (such as SCPH1001.bin).

🎮 PSP Games (via CFW)

Unlike PS1 and PS2 games, PSP games require the installation of two mandatory launchers in addition to the game files.

  • Required format: Only the .iso format. Compressed formats .cso and .zso are not supported.
  • Location: Place your .iso files in the /dev_hdd0/PSPISO/ folder (or on a USB device in a PSPISO folder).
  • Mandatory launchers: The following two launchers must be installed both of them:
    • PSP Minis Launcher: For PSP games in "Mini" format.
    • PSP Remasters Launcher: For PSP games in "Remaster" format (classic UMDs).
  • Requirement: Cobra mode must be enabled in your CFW (enabled by default on Evilnat 4.93).
  • Compatibility: About 60% of the PSP catalog is playable. Check the compatibility list before transferring a game.
💡 Tip: After adding new PSP ISOs, remember to refresh the game list in webMAN MOD so they appear in the "PlayStation®Portable" submenu of the XMB.

⚠️ Special case: PS3HEN

If you were to use PS3HEN instead of CFW, the procedure for PS2 games would be different and more restrictive:

  • You would need to encrypt your PS2 ISOs to .BIN.ENC format.
  • Games would need to be launched via the PS2 Classics Launcher.
✅ Good news: This encryption step is not necessary with your CFW Evilnat.
Chapter 5

🔑 Step 4: License Files (RAP, RIF, EDAT)

The RAP, RIF, and EDAT files are licenses required to activate games or DLCs downloaded in PKG format. Without them, the PS3 refuses to launch the content.

📜 The RAP / RIF Duo

  • The .rap file is the universal license key. It is tied to the content, but not to your console.
  • The .rif file is the personalized license. It is generated by your PS3 from the .rap file and is then linked to your account and your console (via your act.dat). It is this .rif file that the PS3 uses to unlock and launch the game.

🔓 The EDAT File

  • The .edat file (Encrypted Data) is an unlock license used to activate the full content of games or DLCs that were initially trial versions (the "C00" games). It contains the activation information needed to turn a demo into a full game, once the .rap file is installed.

📂 Where to Place Them?

  • .rap files: Place them directly in /dev_hdd0/exdata/.
  • .rif files: Place them in /dev_hdd0/home/[YOUR_USER_ID]/exdata/. The user ID is an 8-digit number (e.g.: 00000001).
  • .edat files:
    • Most common case: Place them in /dev_hdd0/home/[YOUR_USER_ID]/exdata/, at the same location as the .rif files.
    • Specific case (some DLCs): Place them in the game folder, alongside the EBOOT.BIN file:
      • /dev_hdd0/game/[GAME_ID]/USRDIR/
      • or /dev_hdd0/GAMES/[GAME_ID]/PS3_GAME/USRDIR/
⚠️ Important: Never mix .rif and .edat files with .rap files in /dev_hdd0/exdata/. They will be ignored. Each file type has its own dedicated folder.
💡 Tip: Make sure all extensions are lowercase (.rap and not .RAP, .rif and not .RIF, etc.).

⚙️ Installation via PKG

If you have a .pkg file containing the licenses (RAP, RIF, and/or EDAT), the simplest method is to:

  1. Copy the PKG to /dev_hdd0/packages/.
  2. Install it via the Package Manager in the XMB.
  3. Let webMAN MOD automatically place the files in the correct locations.

Chapter 7

🚀 Step 5: Start the Transfer

  1. Connection: Click "Connect" in FileZilla.
  2. Navigation: In the right pane (PS3), open the folder corresponding to your game (e.g.: dev_hdd0/GAMES).
  3. Drag and Drop: From the left pane (your PC), drag the folder or ISO file to the right pane.
  4. Patience: Transfer time depends on the game size and your connection (direct Ethernet = 20-30 MB/s).

🔍 FileZilla Tip: Filter by File Type

To only send .rap files (or any other type) and avoid errors:

  1. Menu View > Filename filters…
  2. Click Add filter and type *.rap in the field.
  3. Confirm. FileZilla will then only show the matching files.

⚡ Optimization: Force Full-Duplex 1000BASE-T on PS3

To save time during FTP transfers, it is essential to force the PS3 to negotiate a Gigabit Ethernet (1000BASE-T) Full-Duplex connection. By default, the PS3 can sometimes settle for 100 Mbit/s, which divides the speed by 10.

🛠️ Configuration on PS3

  1. On the XMB, go to Settings > Network Settings > Internet Connection Settings.
  2. Choose Custom.
  3. Select Wired Connection.
  4. For the Speed and Duplex option, choose 1000BASE-T Full-Duplex.
    • If this option is unavailable or fails, try Auto-Detect.
  5. For the rest (IP Address, DHCP, DNS, MTU), leave on Automatic or Do Not Set if you have no specific configuration.
  6. Save and test the connection.

📡 PC and Network Side

  • Cable: Use a Cat5e or Cat6 cable (Cat5 does not support Gigabit).
  • PC Network Card: Your network card must support Gigabit and be configured for auto-negotiation or 1000BASE-T Full-Duplex.
  • Switch/Router: If you go through a router, it must be Gigabit. In a direct PC-PS3 connection, no switch is needed.

⚠️ Limits to Be Aware Of

  • Even in Gigabit, the maximum throughput to the PS3's internal hard drive is limited to about 19-21 MB/s by the SATA 1.5 Gbps interface.
  • An internal SSD can slightly improve access times, but the SATA limit remains the same.
  • For FileZilla, you can also switch to Active mode (Edit > Settings > FTP > Transfer Mode) if passive mode causes issues.

🖼️ Adding Custom Wallpapers via USB (Simple Method)

To quickly add personal images as a wallpaper on your PS3, the USB method is the most direct and works perfectly, even without FTP. It is ideal for one-time use.

  1. Prepare a USB drive: format it in FAT32.
  2. Create a PICTURE folder at the root of the drive (in uppercase).
  3. Copy your images into this folder. The PS3 officially supports the following formats: JPEG (DCF 2.0/Exif 2.21), PNG, GIF, TIFF, BMP, and MPO (3D photos in MP format). For optimal rendering on an HD screen, prefer 1920x1080 images.
  4. Plug the USB drive into the PS3, then go to the Photo column of the XMB.
  5. Select the USB drive, choose an image, press Triangle and select "Copy". The image will be saved to the PS3's internal storage (Photo folder). You can then find it at any time in the Photo column and set it as wallpaper via Triangle > "Set as Wallpaper", without having to plug the USB drive back in.
💡 If the PS3 does not display the images: place the cursor on the USB drive icon (without pressing X), press Triangle and choose "Display All". This command forces the PS3 to display all compatible files, wherever they are on the device.
⚠️ Tip: This method does not replace complete .p3t themes, but it is perfect for a personal wallpaper. For a complete theme, use the classic installation via /dev_hdd0/theme/ or the XMB theme manager.

🌡️ Step 8: Configuring webMAN MOD (Temperature & Fan)

webMAN MOD offers precise fan control to protect your console. Configuration is done via the /setup.ps3 interface (see IP section below).

🎛️ The 5 Fan Modes

ModeDescriptionAdvantagesDrawbacks
SYSCONThe system manages the fan automatically.Stable, no risk of conflict.Less aggressive cooling.
DYNAMIC (AUTO)webMAN adjusts the speed to reach a target temperature (68°C by default).Powerful and efficient cooling.Can be loud ("airplane effect") on demanding games.
AUTO #2Softer algorithm, speed increases progressively with temperature.Avoids the "airplane" effect and sudden variations.Less effective at cooling quickly.
MANUALYou set a constant fan speed (35% by default).Quiet if speed is low.Does not adapt to load, risk of overheating.
PS2 ManualFixed speed specific to PS2 games.Dedicated cooling for PS2 games.Not applicable to PS3 games.

🌡️ Recommended Temperature Ranges

  • Normal: Between 65°C and 75°C.
  • To avoid: Above 75°C for extended periods can damage components in the long term.
  • DYNAMIC target temperature: Set between 68°C and 72°C. A low value (65°C) = louder but more protective. A high value (75°C) = quieter but less effective.
  • Max speed: Default 80%, adjustable between 40% and 99%.
  • Min speed: Default 25%, adjustable between 20% and 95%.

🎮 In-Game Controller Shortcuts

  • SELECT + UP/DOWN: Adjust the manual fan speed.
  • SELECT + LEFT/RIGHT: Change the target temperature (DYNAMIC mode).
  • L2 + R2 + △: Display CPU/RSX temperature.

💡 Practical Tips

  • If your PS3 is a "Fat" model or if the thermal paste is old, prefer DYNAMIC or AUTO #2 mode.
  • SYSCON mode is the safest if you don't want to worry about configuration.
  • For PS2 games, a speed of 40% is recommended.

🔧 Step 9: Syscalls (CFW Syscalls)

Syscalls are system calls that allow webMAN MOD to access functions normally reserved for the official firmware (such as mounting games, reading temperature, etc.).

🔑 Important Syscalls Used by webMAN MOD

SyscallFunctionUsage
Syscall 8Game mounting (Cobra/Mamba)Mounts ISOs and game folders.
Syscall 383Temperature readingReads CPU/RSX temperatures.
Syscall 389Fan controlAdjusts fan speed.
Syscall 0x1337PS3HEN detectionDetects if PS3HEN is active.

⚠️ When to Disable Them?

  • To play online: Disabling CFW syscalls can reduce the risk of a PSN ban. webMAN MOD allows you to disable them at boot via the "Disable CFW syscalls" option in /setup.ps3.
  • Warning: Disabling CFW syscalls also disables webMAN MOD's dynamic fan control. In this case, the fan remains at the last applied setting.
  • To re-enable syscalls: Go to Custom Firmware Tools and look for the "Allow re-enable syscalls" option. You can also use the R2 + △ combo to restore CFW syscalls.

💡 Best Practices

  • If you don't play online, leave syscalls enabled to enjoy full webMAN MOD control.
  • If you play online, disable syscalls before launching the game, but be aware that you lose dynamic fan control.
  • For PS2 games, syscalls must remain enabled for ISO mounting to work.

🔐 Step 11: FTP Password Management (root)

The default FTP username on PS3 is almost always root. The password depends on the application providing the FTP server. It is important to understand that each application manages its own password: changing webMAN MOD's does not affect multiMAN, and vice versa.

📂 Where Is the Password?

webMAN MOD/dev_hdd0/tmp/wmtmp/password.txtChanges only webMAN MOD's FTP password.
multiMAN / OpenPS3FTP/dev_hdd0/game/OFTP00001/USRDIR/passwordChanges the FTP password used by multiMAN and servers based on OpenPS3FTP.
Apollo Save ToolNo complete FTP serverNo impact: Apollo does not expose a root FTP server.
💡 Good to know: The username remains root. If the password file is empty, the connection is made without a password.

🛠️ How to Change webMAN MOD's Password?

  1. Connect to your PS3 with FileZilla.
  2. Navigate to the /dev_hdd0/tmp/wmtmp/ folder.
  3. Download the password.txt file to your PC.

🎮 Step 14: Fixing Error 80028F10 (PS1 Games)

Error 80028F10 ("Cannot read this game according to the current video output setting") is very common with PS1 games. It occurs mainly due to a conflict between the 720p resolution and the PS1 emulator.

🎯 Solution: Disable the 720p Resolution

  1. Go to Settings > Display Settings > Video Output Settings.
  2. Select your connection type (HDMI, etc.).
  3. Choose Custom (not Automatic).
  4. Uncheck the 720p box.
  5. Leave 1080p and 1080i checked. For a PAL game, leave 576p; for an NTSC game, leave 480p.
  6. Confirm and relaunch the game.
💡 Why does it work? The PS3's PS1 emulator has a known bug with the 720p resolution. By disabling it, we force the PS3 to negotiate a display mode that the game accepts.

⚙️ Complementary Solutions

  • Disable smoothing: Go to Settings > Game Settings > PS/PS2 Settings and set Smoothing to Off.
  • Adjust the display mode: In-game, press the PS button, go to Other Settings > PS/PS2 Settings, and try changing the Display Mode from Full Screen to Normal.
  • Check the region: The error is also common with PAL games (50 Hz) on an NTSC PS3 (60 Hz). Disabling 720p often solves this problem.

📌 To Remember

  • If you need to re-enable 720p for other PS3 games, remember to uncheck it again for problematic PS1 games.
  • Leaving 720p unchecked permanently is a viable solution; most modern PS3 games do perfectly well without it.

❌ Error: "Invalid character sequence received"

Solution: Go back to FileZilla's Site Manager (tab Charset) and make sure "Force UTF-8" is selected. If the problem persists, try the "Use custom charset" option and type UTF8. Also consider updating webMAN MOD to version 1.47.48t.

❌ The PS1 game won't launch
  • Solution 1: Check that the .cue file is next to the .bin with the same name.
  • Solution 2: Try switching the emulator to ps1_netemu.self in /setup.ps3.
  • Solution 3: Disable the 720p resolution (see Step 14).
❌ Error 80028F10 on a PS1 game

Solution: See Step 14 — disable the 720p resolution in the display settings.

❌ FTP connection fails

Solution: Check that the Windows firewall is not blocking FileZilla. Try switching to "Active" mode in FileZilla settings or temporarily disable the firewall.

❌ I can no longer connect via FTP after changing the password
  • webMAN MOD: /dev_hdd0/tmp/wmtmp/password.txt
  • multiMAN / OpenPS3FTP: /dev_hdd0/game/OFTP00001/USRDIR/password

Restart the PS3. If necessary, empty the password file to return to a connection without a password.

❌ The PSN game won't launch despite the PKG being installed

Solution: Check that the .rap file is present in /dev_hdd0/exdata/, that the .rif and .edat files are in /dev_hdd0/home/[YOUR_ID]/exdata/, and that all extensions are lowercase. For certain DLCs, check that the .edat file is also in the game's USRDIR folder.

❌ Fans are stuck at 100% or the PS3 shuts down

Solution: Go to /setup.ps3, select SYSCON, save, and restart the console. If the problem persists, delete the /dev_hdd0/tmp/wm_config.bin file and restart.

❌ NPS Browser doesn't find games

Solution: Check that the TSV URLs are correctly entered and that you have clicked "Sync now" in the options. Make sure your firewall is not blocking NPS Browser.

❌ pkg2zip fails to extract

Solution: Check that the path to pkg2zip.exe is correct in the options and that the parameters are -x {pkgFile} "{zRifKey}".

Cobra 8.5 introduces a new RSX overclocking method that can be applied at console startup.

To persistently overclock the RSX, create a file named overclock.txt and place it at the root of a USB drive or on the internal drive (/dev_hdd0/).

  • The second line is the Memory frequency in MHz.

  • Memory: 300 MHz to 1050 MHz (in 25 MHz "steps").

Chapter 23

📐 Understanding Frequency "Steps" (Core and Memory) of the RSX

When you overclock your PS3's RSX via Cobra 8.5, you cannot choose any frequency. Each component (Core and Memory) has a step, that is, the minimum increment between two allowed values. Any value that does not respect this step will be ignored or rounded by Cobra.

🎯 Core (RSX Core)

  • Original value (stock): 500 MHz
  • Step: 50 MHz
  • Range: 300 MHz to 1050 MHz

This means the only allowed values for the Core are:

300, 350, 400, 450, 500, 550, 600, 650, 700, 750, 800, 850, 900, 950, 1000, 1050

Each value is spaced exactly 50 MHz apart. You cannot enter 575 or 625, as they are not multiples of 50.

🎯 Memory (RSX Memory)

  • Original value (stock): 650 MHz
  • Step: 25 MHz
  • Range: 300 MHz to 1050 MHz

This means the only allowed values for the Memory are:

300, 325, 350, 375, 400, 425, 450, 475, 500, 525, 550, 575, 600, 625, 650,
675, 700, 725, 750, 775, 800, 825, 850, 875, 900, 925, 950, 975, 1000, 1025, 1050

Each value is spaced exactly 25 MHz apart. It is a finer step than for the Core, allowing for more precise tuning.

💡 Why Different Steps?

The Core and Memory of the RSX are two distinct components with their own hardware constraints (frequency multipliers, internal PLL, etc.). The Core is tuned in large increments (50 MHz), while the Memory tolerates finer adjustments (25 MHz). This is a physical limitation of the hardware, not an arbitrary choice.

⚠️ Invalid Values: What Happens?

If you enter a value that does not respect the step, Cobra will ignore it or round it to the nearest valid value. Example:

725   <- invalid for the Core (not a multiple of 50)
875   <- valid for the Memory (multiple of 25)

In this case, 725 for the Core will probably be rounded to 700 or 750, and 875 for the Memory will be accepted as is.

📌 In Summary

  • "In 50 MHz steps": you can only choose values spaced 50 apart (300, 350, 400, etc.).
  • "In 25 MHz steps": you can only choose values spaced 25 apart (300, 325, 350, etc.).
  • Any value that does not respect this step will be ignored or rounded by Cobra.
  • Respecting these steps is mandatory for your overclocking to be applied correctly.
